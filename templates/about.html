About the compliance system

Relational DBMS educational project — Indian Vehicle Import Eligibility & CPD Carnet Management Portal.

{# 1. Project Purpose #}

System purpose & architecture

This application demonstrates how a relational database management system — rather than application layer code — acts as the authoritative decision engine for an institutional customs compliance workflow.

A MySQL stored procedure (CheckEligibility) iterates through active statutory criteria, parses relational requirements via cursors and conditional statements, and logs per-rule compliance outcomes directly to relational audit tables. Flask serves as a lightweight interface; all eligibility business logic is encapsulated in SQL routines and triggers.

The subject matter models the Carnet de Passages en Douane (CPD), an internationally recognised customs transit permit coordinated by the AIT/FIA allowing temporary motor vehicle importation without payment of normal customs duties and taxes across 100+ contracting states, including India.

{# 2. Technology Stack #}

Technology stack

Database Architecture

  • Engine: MySQL 8.0 · InnoDB
  • Schema: 14 normalized tables in Third Normal Form (3NF)
  • Routines: Stored function (CalculateVehicleAge) & stored procedure (CheckEligibility)
  • Integrity: 5 active triggers & 5 database views

Application & Interface

  • Backend: Python 3.11 · Flask
  • Driver: mysql-connector-python with parameterised queries
  • Security: Werkzeug PBKDF2 password hashing & scoped sessions
  • Typography & UI: IBM Plex Sans & IBM Plex Mono
